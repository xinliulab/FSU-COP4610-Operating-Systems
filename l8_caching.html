Why caches work: locality
int sum = 0;
for (int i = 0; i < 32; i++)
sum += a[i];
a[0] … a[31]: 4-byte ints · a cache line holds 64 bytes = 16 ints
Spatial locality: the next a[i] is in the same lineone miss brings in 16 ints; the next 15 hit
Temporal locality: sum, i, and the loop's code are used again and againthey stay in the cache the whole time
Programs reuse what they just touched, and touch what sits next to it

cache miss: 1%check (2) + go to memory (4) = 6 cycles
A high hit rate makes the slow level almost disappear

When does memory see a write?
write-throughwrite to the cache and to memory, right away
write-backwrite to the cache only; memory later, when the line leaves

A puzzle: your memory will be erased
You see a secret number: 7then everything you did is rolled back, and your memory erased
Only one thing survives: the CPU cachewhich lines are in it
Before the erase: touch array[7 × 4096]now the line for slot 7 is in the cache
After: time a read of every slot. Slot 7 is fast
The cache remembers what you touched, even after the rollback

Flush+Reload: read a byte out of the cache
// 1. FLUSH: throw every slot out of the cache
for (i = 0; i < 256; i++) _mm_clflush(&array[i * 4096]);
// 2. the victim touches one slot: array[secret * 4096]
// 3. RELOAD: time a read of every slot
for (i = 0; i < 256; i++)
if (time_read(&array[i * 4096]) < THRESHOLD) secret = i;
Timing one read per slot turns a cache footprint back into a number
